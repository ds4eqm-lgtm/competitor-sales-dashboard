경쟁사 판매량 추적 대시보드 — GitHub + Tampermonkey (시험 운영용 v1.0)
========================================================================
기존 직원 프로그램은 절대로 건드리지 않고 새 GitHub 저장소에서 운영합니다.
Python 설치는 필요하지 않습니다.

[1. 새 GitHub 저장소 만들기]
1) GitHub 로그인 → New repository → 예: competitor-insight → Public → Create.
2) 이 폴더에서 아래 파일/폴더를 새 저장소 최상단에 업로드(Upload files):
   index.html, config/products.json, config/settings.json, data/records.json
   그 외 윈도우용 파일과 사용자 스크립트도 같이 올려두어도 됩니다.
3) Settings → Pages → Build and deployment → Deploy from a branch → main / (root) → Save.
4) 몇 분 후 https://본인계정.github.io/competitor-insight/ 접속.
   * 주의: GitHub Pages의 일반 Public 저장소에는 등록 상품과 재고 이력이 공개됩니다.
     공개가 곤란한 회사 자료는 이 구조에 올리지 마십시오.

[2. 관리용 Chrome 설정]
1) Chrome에서 Tampermonkey 설치.
2) Tampermonkey 대시보드 → 새 스크립트 → 재고추적기.user.js 파일의 전체 내용을 붙여넣고 저장.
   혹은 .user.js 파일을 Chrome에 열어서 Tampermonkey가 인식하면 설치 진행.
3) GitHub Settings → Developer settings → Personal access tokens → Fine-grained tokens.
   * 반드시 새 저장소 단 한 개만 선택.
   * Repository permissions → Contents: Read and write. 기타 권한 불필요.
   * 짧은 유효기간을 사용하고 기한 만료 전 교체.
   * 토큰을 GitHub 코드나 채팅, 스크린샷에 올리지 마세요.
4) Tampermonkey 확장 메뉴에서 ‘연결 설정 · GitHub 계정/저장소/토큰’ 클릭.
   계정, 새 저장소 이름, 토큰 입력. 이 토큰은 직원의 기존 저장소 토큰과 별개입니다.
5) 대시보드 새로고침. 우측 상단 ‘관리 연결됨’이면 URL 등록과 수집 주기 저장 가능.

[3. 자동 실행]
1) 대시보드주소.txt 에 실제 새 GitHub Pages 주소 한 줄 입력.
2) 직원 프로그램을 실행 중인 기존 PC가 아닌, 시험용 회사 PC에서 Chrome에 위 Tampermonkey를 설치.
3) 먼저 대시보드 주소 끝에 #collect를 붙여 직접 접속해서 시험(Chrome 개발자 도구 콘솔 확인).
4) 수집이 잘 되면 자동실행_등록.bat를 실행하여 Windows 작업 스케줄러 등록.
   작업 스케줄러는 10분마다 작동 가능성을 확인하고, 대시보드 설정 간격(10/20/30/40/50/60분)이 지나면 수집을 시작합니다.
5) 윈도우가 실제로 로그인된 Chrome 사용자 세션에서만 수집할 수 있습니다.
   BIOS 자동 부팅만으로는 충분하지 않습니다. 네트워크 연결만 된 로그인 화면에서는 실행이 보장되지 않습니다.
   컴퓨터를 잠그는 것과 로그아웃하는 것은 다릅니다.
6) 자동실행_중지.bat로 일시 중지 가능.
7) 실행기록.log 로 시작 요청 확인. 데이터가 정상 수집됐는지는 GitHub의 data/records.json 확인.

[4. 사용법]
- 대시보드 우측 '관리·설정'을 열고 수집 간격·이상 변동 기준 조정.
- 데코타일/장판/강화마루/필름/기타 카테고리 선택 후 URL을 등록.
- 카테고리 추가 버튼으로 새 분류 추가.
- '켜짐/꺼짐'으로 상품 추적 중지·재개, '제거'로 목록에서 제외.
- 상품명을 클릭하면 실제 상품 페이지로 이동.
- 달력에서 날짜 선택 후 판매량 추정 확인, 시간별 이상 패턴은 아래 표 확인.

[5. 특히 중요한 제한]
- 실제 네이버 상품 재고 수집은 현장 검증되지 않았습니다. 네이버가 공개 페이지에
  재고 데이터를 전달하지 않거나 제공 형식을 바꾸면 수집되지 않을 수 있습니다.
- 현재 수집 엔진은 옵션을 통합한 상품 단위 재고를 대상으로 하는 실험용입니다.
  서로 다른 옵션·상품의 재고가 중복 합산되거나 누락되는지 검증해야 합니다.
- 페이지의 공개된 응답만 관찰합니다. 로그인 제한·접근 차단을 우회해서는 안 됩니다.
- 99개 상품/10분 주기는 CPU·Chrome·GitHub API 한도에 부담을 줄 수 있습니다.
  첫 테스트는 상품 1~3개, 간격 60분부터 시작하세요.
- 동시 재고 변동, 급증·급감은 판매 조작이나 어뷰징의 증거가 아닙니다.
  항상 '검토 필요' 수준으로만 판단하고 다른 증거가 있어야 합니다.
- 설정과 이력은 GitHub에 저장되어 여러 PC에서 조회할 수 있습니다.
- 잘못된 토큰·권한 설정, 비공개 저장소 전환, GitHub Pages 변경 등이 작동을 막을 수 있습니다.
- 기존 직원 PC의 비밀번호 또는 GitHub 토큰을 복사하여 사용하지 마세요.

[파일 설명]
index.html                  웹 대시보드
config/products.json        모니터링 상품 목록(99개 기본 등록)
config/settings.json        수집 간격 및 알림 기준
data/records.json           시간별 재고 이력(처음에는 비어 있음)
재고추적기.user.js           Tampermonkey 수집 및 GitHub 저장
자동실행.ps1                Windows PowerShell 예약 실행 엔진
자동실행_등록.bat           작업 스케줄러에 10분 주기 점검 등록
자동실행_중지.bat           작업 스케줄러 중지
대시보드주소.txt            새 GitHub Pages 주소를 한 줄 입력
